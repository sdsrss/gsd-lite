## 方案

### S1 MCP 注册

- 只通过 Claude Code 自己的 CLI 写：`claude mcp add -s user gsd -- node <RUNTIME_DIR>/src/server.js`；移除用 `claude mcp remove gsd -s user`。
  不直接写 `~/.claude.json`：它是 Claude Code 的活动状态文件（会话随时写），而且路径由它决定——2.1.308 的实现（二进制里的字符串）先看 `<配置目录>/.config.json`
  （非空文件即用），否则 `${CLAUDE_CONFIG_DIR || home}/.claude<后缀>.json`。重写这套解析是 0.17.2/0.18.0 复审抓到过的同类错误。
- 归属判断要读注册内容，CLI 没有 JSON 输出（`mcp get` 只有文本且会启动 server 做健康检查）。所以只读文档写明的位置
  （`CLAUDE_CONFIG_DIR` 设了就 `<CLAUDE_CONFIG_DIR>/.claude.json`，否则 `~/.claude.json`）的顶层 `mcpServers.gsd`，**只用作提示**：
  - 读到且 `args` 含我们的 server 路径 → 已注册，不调用 CLI（自动更新每次都走这条，不需要 PATH 上有 claude）。
  - 其余情况调用 `claude mcp add`；返回"already exists"→ 说明存在一个我们读不到或不是我们的同名注册 → 不动它，输出原因和替换命令，退出非 0。
  - 读错位置只会让我们多调用一次 add 并得到响亮的"already exists"，不会静默改错东西（记忆第 4 条：歧义分支偏向响亮）。
- `claude` 不可运行（ENOENT、超时、非 0）：其余安装照常完成；输出 `✗ MCP server NOT registered` 和可复制的命令；总结行按结果写（记忆 #128）；退出码 1。
  自动更新据此记失败，通知里带原因；这只在需要新注册时发生（0.18 及更早升级上来、或用户删了注册）。
- 插件模式：不注册；读到我们的注册（args 含我们的 server 路径）就 `claude mcp remove gsd -s user`。uninstall 同样按归属移除；读不到时不调用，结尾提示用 `claude mcp list` 确认。
- settings.json：删掉 `mcpServers.gsd`（从没被读过的旧注册）和旧名 `gsd-lite`，与现在的卸载一致。
- 两者都装：0.18 及以前 settings.json 的注册从未生效，所以"插件 + npx"实际只有插件的 server。0.19 起 npx 先装、后装插件且没再跑 install 的用户会看到两套工具。
  保留 0.18.0 的决定（不让 npx 的 server 在插件启用时退场），README 写明切到插件时运行 `npx gsd-lite install`（插件模式下它会移除 user scope 的注册）或 `claude mcp remove gsd -s user`。
- Windows：`claude` 可能是 `claude.cmd`（npm 全局）。`spawnSync` 在 win32 上用 `shell: true` 并给每个参数加双引号。本机无法验证，CHANGELOG 写明。
- 测试：预加载 `tests/git-sandbox.cjs` 把 `tests/fixtures/bin`（假 `claude`）放到 PATH 最前，整套测试碰不到真实 CLI。假 claude 按真实 CLI 的退出码与文件效果实现 `mcp add/remove`
  （写 `${CLAUDE_CONFIG_DIR || HOME}/.claude.json`，格式取自 R1 里真实 CLI 写出的 `{type:'stdio',command,args,env:{}}`），并把每次调用记到同目录的日志。
  契约测试：PATH 上能找到真实 `claude`（跳过假的那个目录）时，用它在 throwaway 配置里安装并 `claude mcp list` 确认 Connected——把假 claude 的模型与真实 CLI 对照；CI 没有 claude 时跳过并说明。
