# 0.20.0：Node 22 下限、action-gh-release v3、更新通知只说真话
状态：进行中（2026-11-01）

## 背景与目标
2026-11-01 剩余工作分析里的第 4、5 项（用户说"按你的建议顺序执行"），加上 0.19.1 评审时用户同意推到 0.20.0 的几项：
- 第 4 项：release.yml 的 action-gh-release v2.6.2 用的是 Node 20 运行时，v0.19.0 的发版日志已经出现弃用提示。
- 第 5 项：Node 20 已于 2026-04-30 停止维护，但 engines 仍是 `>=20.0.0`，CI 也还在测 20。
- F3/F4（0.19.1 第五轮评审）：通过 CLI 以外的方式更新后（`@latest install`、`claude plugin update`），下次会话仍会说"更新失败"或"有更新可用"，说的正是刚装上的版本；节流时重放缓存，也会宣布已经装上的版本"可更新"。
- F5：0.19.1 在 CLI 更新成功后清掉通知，但会把 `check_failed` 一起清掉。
- F6：标签 `vv0.8.2` 去掉一个 `v` 后剩 `v0.8.2`，`requiresSignature` 的 `^v?` 会把它当成 0.8.2，不要求签名。只有在安装版本被读成 `0.0.0` 时才可能被利用。
- 第二轮评审的 LOW：会话通知和缓存提示让用户跑 `gsd update`，但只用 npx 安装的用户 PATH 上没有 `gsd`。

## 范围
- 做：上面各项；CHANGELOG（含迁移说明）；minor 版本号。
- 不做：CI 矩阵是否加 Node 26（单独决定）；runtime 目录迁移、`parallel_available`（第 6 项已决定不做）。

## 方案
- AC3：session-init Phase 4 遇到 `failed` 或 `available` 通知时，用同目录 updater 的 `getCurrentVersion()` 取已安装版本，`compareVersions(installed, notif.to) >= 0` 就不打印（通知照常删除）。出错时退回原来的行为（打印）。这一处就覆盖了 CLI、`@latest install` 和插件三条路径，所以去掉 0.19.1 在 CLI 路径上加的 `clearNotification()`，F5 随之消失。
- AC4：checkForUpdate 的节流分支，只有在 `compareVersions(state.latestVersion, current) > 0` 时才重放缓存。
- AC6：fetchLatestRelease 去掉一个 `v` 后，版本必须匹配 `^\d+\.\d+\.\d+(-[0-9A-Za-z.-]+)?$`，否则返回 `{ error }`。从源头拒绝，`requiresSignature` 的 `v?` 也就无关紧要了。
- AC7：会话通知（available/failed）和缓存提示改用 `npx gsd-lite update --force`：对 npx 安装有效；对全局安装，npx 会运行那个全局副本，也有效。doctor.md:121 同步修改。这是会发给模型的提示词模板，所以整个版本按 L3 处理。
- 发版检查清单：minor 版本 → 0.20.0；CHANGELOG 顶部写明 Node 20 用户该怎么办，回退方式是 `npx gsd-lite@0.19.1 install` 加 `PLUGIN_AUTO_UPDATE=1`；在 Node 20 上安装时 npm 会提示 EBADENGINE。
