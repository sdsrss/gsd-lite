# 0.20.2：更新器在私有临时目录里解包和运行
状态：已发布（v0.20.2，2026-11-02）

## 背景与目标
`downloadAndInstall`（hooks/gsd-auto-update.cjs）把发布包解到 `os.tmpdir()` 下一个以时间命名的目录，并沿用已经存在的同名目录，然后从里面运行 `install.js`。临时目录应当由更新器自己新建、名字随机、只有当前用户能访问。同一个命名方式也让同一毫秒开始的两次更新共用一个目录，这是 0.20.1 评审时 Node 26 上偶发失败的原因（机制能复现；那次失败没有日志，无法确认就是它）。

## 范围
- 做：
  - `downloadAndInstall` 改用 `fs.mkdtempSync(path.join(os.tmpdir(), 'gsd-update-'))`：目录名随机，只有当前用户能访问（0700），路径已存在时不会沿用。
  - CHANGELOG 0.20.2；改正 0.20.0 条目里"npm 在每日更新和插件更新时不警告"的错误说法（D#667 第 7 条）。
- 不做（D#667 其余各条的处理见"决策与进展"）：
  - CLI 在插件模式下报 npx 包自己的版本（D#667 第 2 条）：要从多条插件记录里选出正确的一条，0.10.0 在这块两次方案被否，不和安全修复放在同一个版本里。
  - 将来第一个用到 Node 22 特性的版本在旧 Node 上明确报错：仍按 0.20.1 的决定，做那个版本时加；为防止遗忘，写进发版手册。

## 方案
- `let tmpDir = null;`，在 try 里 `tmpDir = fs.mkdtempSync(...)`，finally 里只在 `tmpDir` 有值时删除。`mkdtempSync` 抛错时（TMPDIR 不可写等），走现有的 catch，返回 false。
- 不把临时目录挪进 `~/.claude/gsd/`：install.js 会整体替换那个目录，而 install.js 正是从临时目录里运行的。
- 0.20.2 这次更新本身仍由旧更新器执行；从 0.20.2 开始的更新才用新目录。CHANGELOG 只写"0.20.2 的更新器"做什么。
